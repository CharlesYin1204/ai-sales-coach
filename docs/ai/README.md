# AI 功能与运维说明

## 已部署功能

- 管理员模型管理：新增、编辑、启停、选择默认模型、真实连接测试、查询供应商模型目录、查看最近200次调用。入口 `/admin/ai-models`。
- AI销售助手：多轮聊天、切换模型、关联有权访问的接待对话、保存个人会话历史。入口 `/app/assistant`。
- 接待分析：按后台规则维度生成结论、原文证据、覆盖分、客户需求、亮点、风险及下一步建议。服务端核对证据为指定原文行的连续片段；格式或证据不合法则报错，不写入结论。
- 录音转写：Whisper真实识别；仅录音时开始分析会先识别，也可单独转写。支持20MB以内MP3/WAV/M4A/OGG/WebM；格式还需供应商接受。不自动区分说话人，须核对角色、金额和时间。
- 辅导方案：人工确认或纠正结论后，由AI填写可编辑的任务草稿；用户核对并点击创建后才生成任务。
- 报表解读：使用服务端按当前角色统计的7/30/90天数据生成问题分析和行动建议，前端传入的伪造统计不会被采用。
- 历史模拟对话保留来源标记；“创建AI复盘副本”可重新分析，同时保留原记录的人工复核与任务。

## 模型配置

| 类型 | API模型名称 | 初始状态 |
| --- | --- | --- |
| 对话、分析、辅导、报表 | gpt-5.6-luna | 默认，真实测试通过 |
| 备用对话模型 | claude-opus-5-thinking | 启用，真实测试通过 |
| 语音转写 | gpt-4o-transcribe | 默认，真实录音测试通过 |
| 备用转写 | whisper-1 | 保留配置；当前供应商上游负载饱和 |

API地址 `https://api.apilio.ai/v1`，使用根目录用户提供的凭据。按供应商文档 `https://gpt-best.apifox.cn/` 接入 `/chat/completions`、`/audio/transcriptions` 和 `/models`。供应商可能返回规范化模型ID，连接测试展示实际返回值，业务记录与日志保存所配置的模型名称。

密钥在数据库中使用AES-256-GCM加密，解密主密钥 `AI_ENCRYPTION_KEY` 仅保存在服务器 `.env`。管理员接口和页面不回显API密钥；编辑时留空保留旧值。源凭据文本与 `.env` 均为0600且被Git忽略。逻辑备份包含加密值，恢复时须配套保管原主密钥；不要重新生成主密钥覆盖已有配置。

仅允许HTTPS供应商域名；当前允许 `api.apilio.ai`。接入其他服务须由运维核对域名，在 `.env` 设置逗号分隔的 `AI_ALLOWED_HOSTS` 后重启。供应商重定向被拒绝；变更API地址必须重新填写该服务的密钥。

## 部署与测试

```sh
export PATH=/opt/laosiji-runtime/node-v22.16.0-linux-x64/bin:$PATH
npm run db:ai
npm run build
chown -R whaleapp:whaleapp .next
systemctl restart whale-coach
npm test
npm run test:browser:ai
```

`db:ai` 是幂等迁移及首次配置导入，不覆盖已有模型设置。迁移SQL在 `database/migrations/002-ai.sql`。测试调用真实供应商API，会产生用量；使用临时隔离门店/账号并在结束后清理业务数据。`scripts/ai-provider-test.mjs` 可单独检查两个模型和转写。

验收报告：`provider-tests.json`、`api-tests.json`、`browser-tests.json`。截图位于同目录。`scripts/test.mjs` 与 `scripts/browser-flow.mjs` 已升级为真实AI验收脚本；`npm test` 执行完整模块回归，`test:browser:ai` 单独验证AI浏览器流程。

## 失败与限制

调用失败、超时、模型停用或响应校验不通过都会明确提示；不会回退为模拟成功。可修改配置后重试；分析完成的记录只能通过副本重分析。单用户每分钟最多30次、最多2个并发供应商调用；并发限流在单进程内生效，重启会清空；每分钟用量限制查询持久化调用日志。每条分析记录及聊天会话有数据库处理锁。

AI助手只提供建议，没有执行业务修改的工具。聊天只读取当前用户自己的会话和授权关联对话，保留最近12轮作为上下文。AI输出仍需人工复核；覆盖分和模型自报置信度不是销售业绩或校准概率。报表统计包含演示记录。已接入团队知识库和站内通知；硬件采集及外部邮件/短信投递未接入。
